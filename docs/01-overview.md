# ۱) معرفی محصول — Aria SafeOps («ایمن‌کار»)

## ۱.۱ هدف
سامانهٔ یکپارچهٔ **ایمنی فرآیند، مجوز کار الکترونیک (Control of Work) و دانش سازمانی HSE** برای واحدهای عملیاتی نفت، گاز و پتروشیمی. زیردامنه: `hse.aria-ai.ir`. سرور Production: `91.107.130.11` (hostname: `hse`).

گردآوری اطلاعات، تحلیل و آنالیز فرآیندها، و اجرای این پروژه در سال‌های **۲۰۲۴، ۲۰۲۵ و ۲۰۲۶** انجام شده است.

این سند بخشی از خانوادهٔ مستندات پروژه است؛ سند بالادستی (تحلیل بازار، مقایسهٔ کامل NestJS/Symfony، دو سامانهٔ خواهر) در [`../../docs/oil-gas-petrochemical-strategy.md`](../../docs/oil-gas-petrochemical-strategy.md) قرار دارد.

## ۱.۲ چرا Symfony؟
برخلاف سامانهٔ خواهر (Aria PetroOps که NestJS انتخاب شد)، SafeOps با **Symfony 7.4 LTS + API Platform** ساخته می‌شود چون:
- ماهیت این سامانه **گردش‌کار/تأییدیه‌محور** است (مجوز کار، MOC، HAZOP) نه real-time/تله‌متری.
- **Symfony Workflow Component** یک state machine اعلامی توکار می‌دهد که دقیقاً منطبق بر نیاز BPMS این سامانه است (جزئیات: [`03-bpms-workflow.md`](03-bpms-workflow.md)).
- نیازی به OPC-UA/MQTT/Modbus ندارد؛ ضعف اصلی اکوسیستم PHP در IoT اینجا بی‌اثر است.
- معماری **headless**: Symfony فقط API می‌دهد (از طریق API Platform)؛ فرانت‌اند کاملاً جدا و در React 19 + TypeScript + Vite است — دقیقاً هم‌راستا با ترجیح فرانت TypeScript پروژه.

| کارشناس صلاحیت پیمانکار | مدیریت ماتریس آموزش، انقضای گواهی |

## ۱.۶ ارتباط با Aria PetroOps
طبق پیوندهای بین‌سامانه‌ای سند مرجع:
- بلوکه‌کردن صدور مجوز کار روی تجهیزی که در PetroOps آلارم بحرانی/آنومالی باز دارد.
- MOC متصل به رجیستر تگ/دارایی PetroOps.
- در فاز ۲ این پیوندها **عملیاتی** هستند: PetroOps آنومالی باز را به SafeOps می‌فرستد و صدور مجوز روی همان `equipment_tag` مسدود می‌شود.
